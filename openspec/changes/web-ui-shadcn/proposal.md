# Proposal

## Why

`openspec/changes/web-ui/design.md`'s "Component approach" decision picked
hand-styled Bits UI over shadcn-svelte, explicitly because "the fuller
pre-styled kit costs more dependency surface than a few pages need," and
named its own revisit condition: "if the page count grows enough that
hand-styling becomes the bottleneck." The web UI is now at 8 pages
(login, secrets overview, settings, audit log, consumers, changelog,
disclaimer, privacy) plus shared chrome, each with its own ad hoc
Tailwind markup, and `cmd/hush-hush/web/.oxlintrc.json` already enables
`@shadcn/lint`'s rules (`shadcn/no-restyle`, `shadcn/no-raw-colors`,
`shadcn/no-arbitrary-values`, `shadcn/no-inline-styles`,
`shadcn/require-static-classes`) with nothing generated by the shadcn-svelte
CLI for them to actually check.

Researched against the current (2026-09) ecosystem
([shadcn-svelte docs](https://www.shadcn-svelte.com/docs),
[shadcn-svelte/bits-ui relationship](https://github.com/huntabyte/shadcn-svelte/issues/1304),
[Tailwind Plus alternatives](https://www.untitledui.com/blog/tailwind-plus-alternatives),
[Flowbite vs shadcn/daisyUI](https://daisyui.com/compare/flowbite-vs-shadcn/?lang=en)):
Tailwind UI/Tailwind Elements/TailGrids have no Svelte support at all;
daisyUI is CSS-only, with no headless accessibility primitives underneath
it; flowbite-svelte is real Svelte markup but ARIA-by-hand, weaker than
the Bits UI foundation this app already has. shadcn-svelte generates
component _source_ directly on top of Bits UI and Tailwind v4 - both
already dependencies here - so it adds no new runtime dependency surface,
which removes the original objection.

Filed and tracked as
[alrayyes/hush-hush#317](https://github.com/alrayyes/hush-hush/issues/317)
and its eight sub-issues (#318-#325).

## What Changes

- Add `components.json` and generate the shadcn-svelte primitives this UI
  needs (button, input, dialog, alert-dialog, select, table, card, label)
  into `cmd/hush-hush/web/src/lib/components/ui/`, mapped onto the
  existing `src/app.css` design tokens rather than shadcn's defaults.
- Migrate the shared chrome and all 8 existing pages from hand-styled
  markup onto the generated components.
- While migrating the audit log page, convert its object-id and
  actor/caller filters from free-text inputs to `Select` components
  populated from known values (#323).
- While migrating the consumers page, add a direct "add consumer" action
  so a consumer can be created without first referencing it in a secret's
  `used_by` list (#324).
- Supersede `openspec/changes/web-ui/design.md`'s "Component approach"
  decision with a dated note once this change ships.

## Capabilities

### Modified Capabilities

- `web-ui`: its component layer moves from hand-styled Bits UI markup to
  generated shadcn-svelte components; two pages (audit log, consumers)
  also gain new user-facing behaviour (select-box filters, add-consumer)
  as part of their migration.

## Impact

- `cmd/hush-hush/web/components.json`: new.
- `cmd/hush-hush/web/src/lib/components/ui/`: new, generated.
- Every file under `cmd/hush-hush/web/src/routes/` and
  `cmd/hush-hush/web/src/lib/` that currently hand-rolls a button, input,
  dialog, select, table, or card.
- `api/openapi.yaml`: new endpoints for audit-log filter option listing
  and for adding a bare consumer (exact shape decided in `design.md`).
- `internal/api`, `internal/store`: handler/store additions backing the
  two new endpoints above.
- `openspec/changes/web-ui/design.md`: superseding note.
